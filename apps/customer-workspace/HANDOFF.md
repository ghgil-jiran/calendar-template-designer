# 연결 확인 목록

이 파일은 구현 완료 범위와 실제 연결 전 확인할 계약을 구분한다. 운영 DB·인증·비밀값·기존 주문 API를 변경하지 않았다.

1. **신원 전달:** 기존 시스템 로그인 후 사용자 ID/이름 전달·검증 방식, 세션 만료/재진입, 사용자별 프로젝트 소유권.
2. **템플릿 조회:** 게시 상태·버전 고정·학교 정보 필요/필수/필수 교체 설정·자산 접근·엔진 요구 버전. 현재 review API는 실제 고객 카탈로그가 아니다.
3. **저장:** 현재 사용자 요청에 따라 기존 로그인 연결을 보류하고 브라우저 내 프로젝트 저장을 구현했다. 서버 프로젝트 CRUD·사용자 소유권·서버 사진 보존은 후속 과제다.
4. **제외 규칙:** 필수 교체와 사용자 표시 제외의 우선순위, 제외된 연결 개체의 공통 엔진 처리. 현재 review 필수 텍스트는 제외할 수 없음.
5. **일정:** DOCX/XLSX/UTF-8 CSV/TXT 읽기·수정 지원. DOC/XLS는 지원하지 않으며 서버에 자료를 전송하지 않는다.
6. **사진:** 최소 DPI·허용 형식/용량·필수 교체, 프레임 안 crop 저장. 기존 원본을 유지하는 자산 참조 필요.
7. **주문/출력:** 최종본 식별자와 전달 규격, 비동기 인쇄본 생성·검증과 기존 시스템 연결. 공식 member/print 문서와 새 흐름을 대조해야 함.
8. **엔진:** 실제 renderPage 전역/DOM 의존성 분리 후 단일 엔진 연결. 현재 참고 이미지 미리보기는 그 검증을 대신하지 않음.

다음 단계의 실제 저장에는 인증·권한 계약이 필요하다. 개발 화면을 넘어서 임의 사용자 ID로 서버에 데이터를 쓰는 API를 추가하지 않는다.

## 자료 입력 구현 · 2026-11-07

- 학교 정보 → 학사일정 → 사진 → 자료 확인을 연결했다. 입력은 편집 중 메모리에 유지하고, 저장 버튼을 누르면 아래의 브라우저 저장소에 원본과 함께 보관한다. 서버 저장으로 표시하지 않는다.
- 일정: DOCX/XLSX/UTF-8 CSV/TXT, 3MB 이하. 시작·종료일·일정명 수정/추가/삭제 및 읽지 못한 내용 확인. DOC/XLS·암호화·손상 파일은 명시적으로 거절한다.
- 사진: JPG/PNG/WebP, 한 장 25MB·50장·합계 250MB. 원본 보존·선택 취소·픽셀 크기 및 배치 DPI 안내. 서버 업로드는 없으며 브라우저 내 원본 보존을 지원한다.
- 실제 문서를 받으면 템플릿 입력 요구사항과 동일한 편집 권한 정의에서 항목/사진 영역을 도출한다. 프레임 배치를 바꾸지 않고 학교 자료와 사진 소스만 변경한다.
- 페이지 표시는 빌드 때 에디터의 기존 렌더링 함수/호환 처리와 공용 화면 모듈을 읽어 생성한다. 생성 파일은 직접 편집하거나 커밋하지 않는다. 관리자 초기화·저장 API는 고객 앱에 실행하지 않는다.
- 게시 목록 연결은 서버 설정을 별도로 완료한 뒤 활성화한다. `CUSTOMER_CATALOG_MODE=published`에서는 게시 상태 및 고정 버전을 확인하며 조회 실패를 참고 데이터로 숨기지 않는다. 자산 URL은 해당 게시 문서가 참조하는 자산만 발급한다.
- 현재 새 배포의 환경변수 목록은 비어 있다. 실제 게시 목록·운영 DB 조회는 검증하지 못했다. 기존 서비스 템플릿 API도 인증 없이 401을 반환했다. 운영 환경변수·인증·DB 정책은 변경하지 않았다.
- 서버 프로젝트 저장·사진 업로드에는 기존 시스템의 신원 전달/검증과 사용자별 소유권 계약이 먼저 필요하다. 브라우저 내 저장에는 로그인하지 않는다. 관리자 세션을 고객 신원으로 사용하지 않는다.
- 로컬 검증: 일정 형식/유효 날짜/기간/중복, 입력 제외, 원본 불변, 권한, 월별 사진 분리 검사. 샘플 A 스냅샷을 로컬에서 직접 제공한 28면 및 입력 반영 검사는 운영 DB 연동 검증과 구분한다.

## 내 프로젝트 · 브라우저 저장 · 2026-11-07

- 사용자 지시: 기존 우리학교인쇄 로그인 후 진입 구현은 보류. 재배포 후에도 같은 PC·브라우저·주소에서 저장본을 다시 열 수 있게 한다.

- 내 프로젝트: 이름·최근 저장·사진/일정 수, 이어서 작업, 백업 다운로드, 삭제. 삭제는 해당 프로젝트의 파일도 함께 삭제한다.
- `.calendar-backup`: 버전/길이/파일별 SHA-256 검사, 원본 바이너리 포함. 복원은 새 UUID로 생성하여 기존 프로젝트를 덮어쓰지 않는다. 백업은 학교 정보/사진을 포함하므로 개인이 보관하는 파일이다.
- 브라우저 데이터 삭제·시크릿 모드 종료·다른 PC/브라우저/주소에는 자동 공유되지 않는다. 백업으로 이동한다. 동일한 고정 브랜치 주소를 사용해야 한다: https://calendar-customer-workspace-git-p-622c51-gil-gighyun-s-projects.vercel.app
- 저장 시 템플릿 이미지 최대 600개/합계100MB, 한 장30MB, 사용자 사진25MB/50장/합계250MB, 전체350MB. 이미지 보관 실패는 부분 저장 성공으로 숨기지 않는다.
- 검증: 앱 검사20개 및 스타일/타입/빌드 통과. 실제 Chromium 화면에서 사진 원본/57개 자산 보존, 새로고침 복원, 트랜잭션 중 강제 실패 롤백, revision 충돌, 백업 복원/손상 거절, 360px 가로 넘침 없음, 새 BUILD_ID로 재빌드·서버 재시작 후 목록 API503 상태에서 저장 프로젝트/사진 복원 확인. 콘솔 오류0건.
- 위 검증은 로컬 브라우저 검증이다. Vercel READY와 보호된 원격 화면의 직접 조작 검증은 구분한다. 실제 게시 목록·로그인·운영 DB/주문 연동은 여전히 보류다.

## 2026-11-07 · 템플릿 반영 문서 보존

- 원본 source와 입력만 보관하던 저장 구조에 `appliedProject`를 추가했다. 공통 applyMaterials로 만든 전체 달력 문서, 사용자 사진의 영속 참조를 저장한다. 원본/개체 위치/스타일/권한을 보존하며 복원 시 입력과 반영본의 일치를 검사한다. 기존 v1 저장본과 백업은 그대로 읽고 다음 저장에서 반영본을 추가한다.
- 내 프로젝트 목록은 입력 자료 저장본과 템플릿 반영본을 구분한다. 실제 게시/불러온 템플릿은 원본이 없으면 저장 성공으로 표시하지 않는다.
- 에디터 원본(.acdl.json) 로컬 불러오기를 추가했다. 별도의 에디터를 만들거나 관리자 데이터를 공개 저장소에 넣지 않는다. 접근 가능한 이미지/포함 이미지를 사용하며 미해결 acdl-asset:// 또는 blob: 참조는 명시적으로 거절한다. 가져온 원본은 게시 상태를 변경하지 않는다.
- 중요한 제한: Preview의 게시 카탈로그 서버 설정은 여전히 없다. 5개 참고 카드는 실제 템플릿 원본으로 자동 연결하지 않았다. 기존 샘플 A 저장 원본에는 acdl-asset:// 서버 자산 참조가 있어 그대로 로컬 불러오기할 수 없다. 실제 게시 목록과 자산을 사용하려면 후속 서버 조회 설정이 필요하다.
- 기존 로그인 연동, 서버 프로젝트 저장, 개체 편집 화면 구성은 범위 밖이다.

- 이번 검증: 앱 검사23개, 학교명 바인딩을 가진 원본의 실제 공통 렌더 표시/사진 배정/일정/반영본 저장 및 새로고침 복원을 Chromium에서 확인. 테스트 원본은 개인 원본/자산을 공개하지 않는 합성 문서이며, 운영 샘플 A 자산 조회 검증을 대신하지 않는다.

- Supabase 서명 응답의 /object/sign/...와 /storage/v1/object/sign/...를 모두 정확하게 처리한다. 지정된 Supabase 원본과 template-assets 경로만 허용한다. 목록의 acdl-asset 표지도 해석한다.

- 사용자 작업 필요: Vercel > gil-gighyun-s-projects > calendar-customer-workspace > Settings > Environment Variables에서 Preview에 SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY(Secret), CUSTOMER_CATALOG_MODE=published(Config)를 설정. 기존 에디터와 같은 Supabase 프로젝트를 사용한다. 실제 키는 채팅에 요청하지 않는다. 등록 후 새 Preview 배포로 활성화해야 한다.
- 설정 전에는 기존 review 모드를 유지한다. 게시 조회가 활성화되면 실패를 참고 데이터로 숨기지 않는다. 실제 DB의 게시 템플릿 하나를 이용한 화면/사진/재열기 검증은 아직 남아 있다.

- 원본 캐시/버전 일치/실패 재시도 포함 앱 검사29개 및 빌드 통과. 화면 검증에는 실제 28면 샘플 A 문서 구조를 사용하되 비공개 이미지 참조는 로컬 자리 이미지로 바꿨다. 운영 이미지의 외관 검증과 구조/레이아웃 검증은 구분한다.

## 2026-11-08 · 자료 입력 정리/사진 준비 방식 선택

- 사용자 지시: 입력 후 달력 반영 확인 화면 유지. 이를 편집기 대체로 확정하거나 주문 기능을 새로 만들지 않는다. 나머지 입력 문제를 수정하고 Preview에 반영한다.
- 기본 학교명/영문명은 항상 입력한다. 연결된 글자 개체가 없으면 저장만 된다는 안내를 표시한다. 교목·교화는 이름/설명을 각각 묶고 교가 가사 텍스트 항목을 제거하여 이미지 입력을 사용한다.
- 공통 저장 패널의 백업 다운로드를 제거하고 내 프로젝트에 유지. 첫 화면의 개발용 에디터 원본 불러오기를 제거하되 과거 imported 프로젝트/백업 형식은 계속 읽는다.
- 사진: 보관함 다중 업로드와 학교 공통 이미지 입력, 사진만 먼저 올리기/페이지별 배정 선택. 선택/사진/배정은 저장·백업·복원에 포함되며 방식을 바꿔도 배정을 지우지 않는다. 현재 편집기 끌어넣기는 후속 단계다.
- 기존 school-image 역할의 전경 이미지를 인식한다. 동일한 학교 이미지 연결을 공유하는 개체에 반영하며 위치/크기를 보존한다. 연결된 교체 영역이 전혀 없으면 학교 자료 슬롯으로 보관하고 해당 사실을 안내하며 배경 개체를 만들지 않는다. 명시적으로 excluded인 학교 자료는 만들지 않는다. 월별 사진은 3월 앞면/뒷면 등으로 표시한다.
- 미배정 필수 사진이 있어도 반영 결과 확인·초안 저장은 가능하며 미배정/기본 사진 잔존 안내를 표시한다. 최종 완료/주문 구현 시 필수 자료 최종 검사를 연결해야 한다.
- 저장 schema/DB version은 유지하며 optional photoMode와 bindingVersion=2를 추가했다. 예전 반영본은 구조·파일 유효성을 확인해 읽고, 다음 저장부터 새 연결 규칙으로 검증한다. 이전 입력값을 지우지 않고 입력 항목 정의만 현재 기준으로 갱신한다.
- 앱 검사33개와 타입/스타일/빌드 통과. Chromium에서 영문명/묶음/교가/표지 업로드/월 라벨/방식 전환/반영 확인/저장 후 새로고침과 사진·배정·방식 복원/내 프로젝트 백업 유지/360px 검증. 실제 원격 화면 조작 검증과 로컬 API fixture 검증은 구분한다.
- 게시 노출 기준과 기존 템플릿 상태는 변경하지 않았다.

## 2026-11-08 · 사진 보관 구분과 페이지별 미리보기 배정

- 사용자 승인: 공통 이미지/월력 뒷면 사진 보관함 분리, 페이지를 보며 선택하고 적용하는 사진 전용 흐름 구현. 전체 개체 편집기는 만들지 않고 기존 반영 확인 흐름을 유지한다.
- 원본 사진 category(school/monthly/both), 적용 대기 photoSelections(선택 해제는 null), photoPageId를 optional 필드로 저장/백업/복원한다. DB와 프로젝트/백업 스키마 버전은 유지한다. 기존 사진·배정은 삭제하지 않는다.
- 공통 이미지는 연결된 모든 페이지 ID를 유지하고, 페이지별 항목은 실제 연결과 교체 권한을 바탕으로 표시한다. 연력이라도 실제 연결 사진이 있으면 표시하고, 없으면 사진 선택란 없이 안내한다. 학교 상징 항목 수를 고정하지 않는다.
- 사진 선택은 대기 상태이고 현재 페이지 적용 버튼으로 해당 페이지의 선택만 반영한다. 다른 페이지의 대기는 유지된다. 적용 전 다음 단계 진입은 막고 적용 또는 명시적 선택 취소를 안내한다. 사진 삭제 시 사용 중이면 확인하고 관련 배정/대기를 정리한다.
- 현재 미리보기는 템플릿 원본이 아니라 학교 입력·일정·적용 사진이 들어간 동일 문서/공통 렌더러를 사용한다. 공통 이미지가 다른 면에도 반영됨을 안내한다.
- 클라이언트 검사36개와 타입/스타일/빌드 통과. 페이지 연결 관계/페이지별 적용의 독립성/사진 분류 및 대기 선택의 백업 복원을 검사했다. 로컬 화면 검증과 원격 실제 DB/자산 검사는 구분한다.

- 추가 검증: 공통 원본 imageForBinding에서 current 분기가 일반 monthlyImages 분기에 먼저 잡히는 문제를 수정했다. 공유 Master의 3월/4월 사진을 분리한다. 실제 원본 함수를 읽는 검사를 추가해 37개 통과. 로컬 브라우저에서 보관함 분리/연력 0항목/상징 3항목/적용 전후/페이지 이동/대기 선택 저장·복원/적용 결과 복원/360px을 확인했다.

## 2026-11-08 · 고객 문구·연락처·일정 입력 UI 정리

- 카드에는 작성용 설명 대신 고객용 달력 소개를 표시. 상세 이동은 ‘이전 디자인 보기’, 확대는 ‘전체 페이지 크게 보기’로 정리했다. DB 템플릿 설명/게시 상태는 변경하지 않는다.
- 학교 기본 정보는 빈칸이면 샘플 유지/표시 제외 시 숨김을 안내. 새 입력은 omitEmptyContacts=true로 빈 연락처와 대체 텍스트를 숨긴다. 필수 연락처 검증은 유지하며 기존 저장본의 빈칸 처리 방식은 보존한다. 배경 이미지의 글자는 대상이 아니다.
- 일정 파일 선택/붙여 넣기를 나란한 버튼으로 제공하고 일정 확인을 접을 수 있게 했다. 파일 해석·샘플 일정 겹침은 변경하지 않았다.
- 학교 입력의 calendarDisplay에 공휴일/기념일/24절기/음력 선택을 저장한다. 초기값은 원본 설정을 상속(미지정은 모두 켬), 공통 렌더러의 settings.calendarData에 반영. 원본 데이터/표시 영역이 없거나 이미지에 포함된 글자는 이 선택으로 생성/변경하지 않는다. 템플릿 기본 생성 코드는 이미 미지정 항목을 켬으로 처리하므로 변경하지 않는다.
- 앱 검사40개, 타입/스타일/빌드 통과. 로컬 브라우저에서 버튼/접기/선택 저장 후 재열기/기존 사진 배정 흐름/360px 가로 넘침 없음 확인. 실제 원격 서버 검사는 Preview 빌드에서 수행하며 원격 브라우저 확인과 구분한다.
