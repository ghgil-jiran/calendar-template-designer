# 연결 확인 목록

이 파일은 구현 완료 범위와 실제 연결 전 확인할 계약을 구분한다. 운영 DB·인증·비밀값·기존 주문 API를 변경하지 않았다.

1. **신원 전달:** 기존 시스템 로그인 후 사용자 ID/이름 전달·검증 방식, 세션 만료/재진입, 사용자별 프로젝트 소유권.
2. **템플릿 조회:** 게시 상태·버전 고정·학교 정보 필요/필수/필수 교체 설정·자산 접근·엔진 요구 버전. 현재 review API는 실제 고객 카탈로그가 아니다.
3. **저장:** 현재 사용자 요청에 따라 기존 로그인 연결을 보류하고 브라우저 내 프로젝트 저장을 구현했다. 서버 프로젝트 CRUD·사용자 소유권·서버 사진 보존은 후속 과제다.
4. **제외 규칙:** 필수 교체와 사용자 표시 제외의 우선순위, 제외된 연결 개체의 공통 엔진 처리. 현재 review 필수 텍스트는 제외할 수 없음.
5. **일정:** DOCX/XLSX/UTF-8 CSV/TXT 읽기·수정 지원. DOC/XLS는 지원하지 않으며 서버에 자료를 전송하지 않는다.
6. **사진:** 최소 DPI·허용 형식/용량·필수 교체, 프레임 안 crop 저장. 기존 원본을 유지하는 자산 참조 필요.
7. **주문/출력:** 최종본 식별자와 전달 규격, 비동기 인쇄본 생성·검증과 기존 시스템 연결. 공식 member/print 문서와 새 흐름을 대조해야 함.
8. **엔진:** 실제 renderPage 전역/DOM 의존성 분리 후 단일 엔진 연결. 현재 참고 이미지 미리보기는 그 검증을 대신하지 않음.

다음 단계의 실제 저장에는 인증·권한 계약이 필요하다. 개발 화면을 넘어서 임의 사용자 ID로 서버에 데이터를 쓰는 API를 추가하지 않는다.

## 자료 입력 구현 · 2026-11-07

- 학교 정보 → 학사일정 → 사진 → 자료 확인을 연결했다. 입력은 편집 중 메모리에 유지하고, 저장 버튼을 누르면 아래의 브라우저 저장소에 원본과 함께 보관한다. 서버 저장으로 표시하지 않는다.
- 일정: DOCX/XLSX/UTF-8 CSV/TXT, 3MB 이하. 시작·종료일·일정명 수정/추가/삭제 및 읽지 못한 내용 확인. DOC/XLS·암호화·손상 파일은 명시적으로 거절한다.
- 사진: JPG/PNG/WebP, 한 장 25MB·50장·합계 250MB. 원본 보존·선택 취소·픽셀 크기 및 배치 DPI 안내. 서버 업로드는 없으며 브라우저 내 원본 보존을 지원한다.
- 실제 문서를 받으면 템플릿 입력 요구사항과 동일한 편집 권한 정의에서 항목/사진 영역을 도출한다. 프레임 배치를 바꾸지 않고 학교 자료와 사진 소스만 변경한다.
- 페이지 표시는 빌드 때 에디터의 기존 렌더링 함수/호환 처리와 공용 화면 모듈을 읽어 생성한다. 생성 파일은 직접 편집하거나 커밋하지 않는다. 관리자 초기화·저장 API는 고객 앱에 실행하지 않는다.
- 게시 목록 연결은 서버 설정을 별도로 완료한 뒤 활성화한다. `CUSTOMER_CATALOG_MODE=published`에서는 게시 상태 및 고정 버전을 확인하며 조회 실패를 참고 데이터로 숨기지 않는다. 자산 URL은 해당 게시 문서가 참조하는 자산만 발급한다.
- 현재 새 배포의 환경변수 목록은 비어 있다. 실제 게시 목록·운영 DB 조회는 검증하지 못했다. 기존 서비스 템플릿 API도 인증 없이 401을 반환했다. 운영 환경변수·인증·DB 정책은 변경하지 않았다.
- 서버 프로젝트 저장·사진 업로드에는 기존 시스템의 신원 전달/검증과 사용자별 소유권 계약이 먼저 필요하다. 브라우저 내 저장에는 로그인하지 않는다. 관리자 세션을 고객 신원으로 사용하지 않는다.
- 로컬 검증: 일정 형식/유효 날짜/기간/중복, 입력 제외, 원본 불변, 권한, 월별 사진 분리 검사. 샘플 A 스냅샷을 로컬에서 직접 제공한 28면 및 입력 반영 검사는 운영 DB 연동 검증과 구분한다.

## 내 프로젝트 · 브라우저 저장 · 2026-11-07

- 사용자 지시: 기존 우리학교인쇄 로그인 후 진입 구현은 보류. 재배포 후에도 같은 PC·브라우저·주소에서 저장본을 다시 열 수 있게 한다.
- IndexedDB `school-calendar-customer-projects` v1, `projects`/`summaries`/`files`. 학교 정보·숨김 항목·일정·사진 원본/배정·입력 단계·선택 템플릿/버전·공통 문서 및 이미지 스냅샷을 보관한다. 파일은 Blob으로 보관하며 일시적 object URL은 저장하지 않는다.
- 저장은 세 저장소의 단일 트랜잭션으로 완료되고 revision 충돌·용량 초과·파일 저장 실패 때 기존 저장본을 유지한다. 새로고침/페이지 이탈에는 미저장 변경 알림을 사용한다. DB/schema 변경 시 명시적 마이그레이션이 필요하며 배포 초기화나 deleteDatabase를 추가하지 않는다.
- 내 프로젝트: 이름·최근 저장·사진/일정 수, 이어서 작업, 백업 다운로드, 삭제. 삭제는 해당 프로젝트의 파일도 함께 삭제한다.
- `.calendar-backup`: 버전/길이/파일별 SHA-256 검사, 원본 바이너리 포함. 복원은 새 UUID로 생성하여 기존 프로젝트를 덮어쓰지 않는다. 백업은 학교 정보/사진을 포함하므로 개인이 보관하는 파일이다.
- 브라우저 데이터 삭제·시크릿 모드 종료·다른 PC/브라우저/주소에는 자동 공유되지 않는다. 백업으로 이동한다. 동일한 고정 브랜치 주소를 사용해야 한다: https://calendar-customer-workspace-git-p-622c51-gil-gighyun-s-projects.vercel.app
- 저장 시 템플릿 이미지 최대 600개/합계100MB, 한 장30MB, 사용자 사진25MB/50장/합계250MB, 전체350MB. 이미지 보관 실패는 부분 저장 성공으로 숨기지 않는다.
- 검증: 앱 검사20개 및 스타일/타입/빌드 통과. 실제 Chromium 화면에서 사진 원본/57개 자산 보존, 새로고침 복원, 트랜잭션 중 강제 실패 롤백, revision 충돌, 백업 복원/손상 거절, 360px 가로 넘침 없음, 새 BUILD_ID로 재빌드·서버 재시작 후 목록 API503 상태에서 저장 프로젝트/사진 복원 확인. 콘솔 오류0건.
- 위 검증은 로컬 브라우저 검증이다. Vercel READY와 보호된 원격 화면의 직접 조작 검증은 구분한다. 실제 게시 목록·로그인·운영 DB/주문 연동은 여전히 보류다.

## 2026-11-07 · 템플릿 반영 문서 보존

- 원본 source와 입력만 보관하던 저장 구조에 `appliedProject`를 추가했다. 공통 applyMaterials로 만든 전체 달력 문서, 사용자 사진의 영속 참조를 저장한다. 원본/개체 위치/스타일/권한을 보존하며 복원 시 입력과 반영본의 일치를 검사한다. 기존 v1 저장본과 백업은 그대로 읽고 다음 저장에서 반영본을 추가한다.
- 내 프로젝트 목록은 입력 자료 저장본과 템플릿 반영본을 구분한다. 실제 게시/불러온 템플릿은 원본이 없으면 저장 성공으로 표시하지 않는다.
- 에디터 원본(.acdl.json) 로컬 불러오기를 추가했다. 별도의 에디터를 만들거나 관리자 데이터를 공개 저장소에 넣지 않는다. 접근 가능한 이미지/포함 이미지를 사용하며 미해결 acdl-asset:// 또는 blob: 참조는 명시적으로 거절한다. 가져온 원본은 게시 상태를 변경하지 않는다.
- 중요한 제한: Preview의 게시 카탈로그 서버 설정은 여전히 없다. 5개 참고 카드는 실제 템플릿 원본으로 자동 연결하지 않았다. 기존 샘플 A 저장 원본에는 acdl-asset:// 서버 자산 참조가 있어 그대로 로컬 불러오기할 수 없다. 실제 게시 목록과 자산을 사용하려면 후속 서버 조회 설정이 필요하다.
- 기존 로그인 연동, 서버 프로젝트 저장, 개체 편집 화면 구성은 범위 밖이다.

- 이번 검증: 앱 검사23개, 학교명 바인딩을 가진 원본의 실제 공통 렌더 표시/사진 배정/일정/반영본 저장 및 새로고침 복원을 Chromium에서 확인. 테스트 원본은 개인 원본/자산을 공개하지 않는 합성 문서이며, 운영 샘플 A 자산 조회 검증을 대신하지 않는다.
