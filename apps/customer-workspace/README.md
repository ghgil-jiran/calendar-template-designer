# 신규 사용자 서비스 · 첫 화면 검토

템플릿 에디터 저장소 안의 독립 Next.js 앱이다. 기존 사용자 서비스·에디터의 실행 경로를 변경하지 않는다.

현재 구현: Hero, 5종 검토용 카탈로그, 페이지 구성 설명, 전체 28면 미리보기, 준비 자료 안내, 필수/선택 학교 정보·표시 제외, 입력 확인 화면. 키보드로 미리보기 이동/닫기가 가능하다.

현재 카탈로그는 `/api/workspace/catalog`에서 제공하는 명시적인 review 데이터이다. 실제 게시 목록으로 가장하지 않는다. 2026-11-07 사용자가 참고 이미지 포함 브랜치 저장을 명시적으로 승인했다. 샘플 A 확인용 PDF에서 추출한 28개 저용량 미리보기를 포함한다. 원본 PDF·원본 사진·템플릿 JSON은 포함하지 않는다. 추가 디자인의 실제 시안이 아니다. 최종 렌더링·인쇄 품질 근거로 사용하지 않는다.

입력은 메모리에만 유지한다. 저장 완료 표시, 임의 로그인, 관리자 세션 재사용, 사용자 자료 전송, 주문 전송, 로컬 캐시 저장은 구현하지 않았다. 내 프로젝트는 미연결 안내만 제공한다. 실제 저장이 필요한 다음 단계에서는 승인된 신원·서버 저장 계약을 연결해야 한다.

## 실행

이 폴더에서 `npm ci`, `npm run dev`. 주소는 http://localhost:3000 이다.

검사: `npm test`, `npm run typecheck`, `npm run build`. Node 24에서 TypeScript 원본을 직접 검사하며, Next.js 런타임 요구사항은 package.json을 따른다.

독립 Vercel 프로젝트의 Root Directory를 `apps/customer-workspace`로 설정한다. 기존 디자이너 프로젝트의 Root Directory·루트 rewrites·Production을 변경하지 않는다. Preview만 배포한다.

## 다음 연결

- 기존 시스템의 사용자 신원 전달·작업 소유권 확인.
- 실제 게시 템플릿과 학교 필드 설정을 새 API 계약에 연결. 에디터 관리자 API를 고객에게 그대로 노출하지 않음.
- 프로젝트 서버 저장 및 복구 캐시. 입력 화면의 현재 데이터와 명시적 제외 상태를 각각 보존.
- 일정 파일 해석/표 편집, 학교 상징·사용자 사진 업로드.
- 에디터 네이티브 프로젝트와 동일 렌더링 엔진 연결. 이 앱에 별도 달력 렌더러를 구현하지 않음.
- 최종본 확정·출력 Worker 이전·주문 전달.
