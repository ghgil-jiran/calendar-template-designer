# V2 매핑 초안 저장 경계

상태: 검토용 계약. 실제 DB·API·인증 연결 및 SQL 적용은 아직 하지 않았다.

## 독립 자원

매핑 후보는 `calendar_v2_migration_drafts`라는 별도 자원에만 저장한다. 기존 `templates`, `template_versions`, `template_assets` 및 사용자 프로젝트 테이블에 쓰지 않는다.

최소 필드:

| 필드 | 의미 |
| --- | --- |
| id | 새 V2 초안 UUID. 구버전 템플릿 ID를 재사용하지 않음 |
| revision | 동시 편집 충돌 검사용 정수. 1부터 시작 |
| candidate | 고정된 원본과 비실행 매핑 계획. 운영 템플릿이 아님 |

수정은 예상 revision과 실제 revision이 일치할 때만 허용한다. 신규 저장 충돌은 덮어쓰지 않는다. 저장 어댑터는 전송 기능을 명시적으로 주입받으며 구버전 저장 모듈을 불러오지 않는다.

## 데이터 연결 전 조건

- 실제 현재 템플릿 저장본, 연결 자산, 복구 기준 확인.
- V2 DB 격리 위치 및 접근 권한 확정. 같은 DB의 별도 테이블과 별도 Supabase 프로젝트는 보안상 동등하지 않다.
- 새 서버 인증과 쓰기 경계 확인. 후보에는 전체 원본이 있으므로 공개 API나 공개 저장소에 올리지 않는다.
- 코드 테스트의 메모리 저장 검증은 Supabase 영속 저장 검증을 대신하지 않는다.
- 기존 환경변수를 새 프로젝트에 복사하지 않는다. V2 전용 연결 변수와 인증 경로가 준비된 뒤 설정한다.

## 변환 단계

읽기 전용 조사 → 매핑 후보 작성 → 불명확한 개체·암묵 생성 규칙 검토 → 실행 가능한 V2 문서 계약으로 변환 → 동일 결과 비교 → 새 초안 저장.

현재 구현은 매핑 후보 작성까지만 지원한다. 원본 개체 속성·알 수 없는 값·월별 배치 차이는 보존하며 스타일 묶음이나 월별 색상 연결을 임의로 추론하지 않는다. 배경은 개체 스타일 후보에서 분리 표시하되 원본 자산을 복사·백업한 것으로 간주하지 않는다.
