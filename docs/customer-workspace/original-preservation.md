# 사용자 교체 사진 원본 보관

2026-11-17. 기존 사용자 서비스의 원본 File·사진 배정·배치·크롭은 유지한다.

- 사진 등록 단계와 편집기에서 자동 저장한다. 원본 서버 보관 확인 후 브라우저의 프로젝트·파일을 하나의 IndexedDB 트랜잭션으로 저장한다. 서버 전송 실패 시 저장 완료 표시를 하지 않으며 이전 로컬 저장본과 편집 중 원본 File을 보존한다.
- 원본은 변환하지 않고 SHA-256/바이트 수/MIME로 기록한다. 앞·뒷면이 같은 사진을 쓰면 한 원본을 공유한다. 원격 저장 직후 파일을 다시 읽어 해시가 같은지 확인한다.
- `/api/workspace/originals`는 1MiB 분할 업로드와 원본 재읽기를 제공한다. 서버 전용 Supabase 설정을 사용한다. `calendar-customer-originals` 버킷은 private이어야 하며 처음 사용 시 private으로 생성한다. Public 설정이면 저장을 거부한다. 공개 URL은 만들지 않는다.
- 현재 서비스에는 회원별 프로젝트 인증이 없다. 프로젝트마다 임의의 256비트 접근 키를 생성하고 Authorization 헤더로만 전달한다. 저장 경로에는 키의 해시만 사용한다. 키는 로컬 프로젝트/프로젝트 백업 안에 보관하며 URL·화면·로그에 넣지 않는다. 다른 프로젝트 키로는 원본을 조회할 수 없다. 계정 로그인이나 계정 간 공유 기능을 새로 제공하는 것은 아니다.
- 로컬 원본이 누락·변조되면 저장된 참조로 원격 원본을 복구하고 해시를 검증한다. 프로젝트 정보와 접근 키까지 브라우저에서 삭제된 경우 자동 검색할 수 없다. 다른 브라우저에서의 전체 프로젝트 복원은 기존 프로젝트 백업을 이용한다. 편집 정보의 원격 동기화·회원 로그인은 이번 범위가 아니다.
- 한 장 25MB, 프로젝트 보관 원본 합계 350MB. 기존 원본은 자동으로 지우지 않는다. 새 파일이 누적 한도를 넘으면 저장 실패를 명시한다. 오래된 원본의 정리·회원 계정별 보관 정책은 별도 설계가 필요하다.
- 브라우저 원본 File, 저장·복원된 File, 공통 Runtime에 전달하는 사진 참조는 동일 바이트다. 신규 서비스의 실제 주문·인쇄 접수 연결은 아직 없으며 최종 Worker 출력의 실물 검증 완료를 뜻하지 않는다.

검증: 원본 바이트 동일성, 분할 누락·변조 거부, 비공개 설정, 프로젝트별 접근 분리, 동일 원본 중복 제거, 복구 시 해시 확인, 실패 시 성공 참조를 반환하지 않는 검사.
