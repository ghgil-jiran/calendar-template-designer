# 사용자 학사일정 읽기와 월별 확인

2026-11-08 검토 및 구현. 사용자 편집기 브랜치의 customer-workspace 범위.

## 기존 구현 비교

- 기존 사용자 서비스 `ghgil-jiran/-v1.1/src/app/api/ai/schedule-extract/route.ts` (검토한 blob dc9d1458d835a6bdef7393b75661ff8b5ac8782b): XLSX/XLS는 SheetJS, DOCX는 mammoth, HWPX는 ZIP/XML와 셀 좌표 복원, PDF는 문서 입력으로 AI 분석. 두 분석 결과 보완, 누락 의심 재시도, 공휴일 제외, 같은 이름 기간 병합, 종료일 없는 주간 보정이 구현되어 있다. HWP/DOC 바이너리는 미지원이다.
- 같은 서비스 `src/lib/schedule/hwpx-grid.ts`: 한글 표의 월/주차/요일/수업일수 숫자를 구별하기 위해 요일별 셀 좌표로 날짜를 먼저 정한다. 표를 평문으로만 합치는 것보다 날짜 밀림을 줄인다.
- 템플릿 에디터 `apps/designer-studio/schedule-file-parser.js`: XLSX 셀 좌표·공유 문자열·Excel 날짜를 읽고 월별 표를 텍스트로 바꾸는 기본 읽기. 복잡한 원고는 `schedule-api-client.js` → 서버 `api/schedule-extract.js` → 위 사용자 서비스의 공통 AI API를 사용한다. 에디터가 DOCX/TXT만 읽는 구조는 아니었다.
- 새 customer-workspace는 기존에 DOCX/XLSX/CSV/TXT의 제한된 텍스트 파싱만 사용했다. 문장, 달력 격자, 복잡한 병합 표, 한 칸 여러 일정이 있는 원고를 놓치기 쉬웠다.

## 반영

- 파일 업로드는 기존 사용자 서비스의 `/api/ai/schedule-extract`를 재사용한다. 사용자의 파일은 해당 서버에서 분석한다. 서버 전용 `SCHEDULE_EXTRACTION_ORIGIN`으로 주소를 지정할 수 있으며 기본 주소는 기존 사용자 서비스 Production이다. API 키를 새 앱이나 클라이언트로 복사하지 않는다.
- 지원: DOCX/XLSX/XLS/HWPX/PDF/CSV/TXT, 한 번 3MB. 구형 HWP/DOC는 변환 안내. 별도 파서 의존성을 중복 추가하지 않는다.
- 공통 API 응답의 날짜·제목·기간을 검증하고, 완전 중복을 제거한다. 기존 API의 2027/2028년 고정 결과를 선택한 학사연도/시작 월로 맞춘다. 존재하지 않는 윤일 등은 다른 날짜로 임의 변경하지 않고 제외 안내한다.
- 공통 분석 실패 시 DOCX/XLSX/CSV/TXT는 기존 기본 읽기를 사용하되 제한된 결과임을 표시한다. HWPX/PDF/XLS는 변환·재시도를 안내한다. 실패한 요청으로 기존 일정이나 추가 전 결과를 지우지 않는다.
- 붙여 넣기는 명확한 날짜별 목록이면 기본 읽기, 그렇지 않으면 같은 AI 분석을 사용한다. 일정 추가는 기존 목록과 합치며 날짜/기간/일정명이 같은 항목은 중복 추가하지 않는다.
- 월별 확인을 기본으로 한다. 12개월은 선택한 달력의 시작 월부터 구성하며 전체 보기와 기간 밖·확인 필요 보기를 제공한다. 두 달에 걸친 일정은 양쪽 월에 동일 ID로 보인다. 수정·삭제는 원본 한 건에 반영한다. 월별 추가는 선택 월의 1일로 시작하며 날짜를 변경할 수 있다.

## 한계와 확인

- 기존 공통 AI의 주간 종료일 추정, 기간 병합, 공휴일 제외 규칙을 그대로 사용한다. UI에서 이를 안내하고 원본 대조를 요구한다. 이 결과를 확정 정답으로 간주하지 않는다.
- 스캔 품질·복잡한 병합 표·여러 일정이 섞인 칸에 따라 누락/기간 오해가 남을 수 있다. 일부 기본 읽기는 표 구조를 충분히 보존하지 못한다.
- 학사연도에 맞춰 파일의 연도가 변경될 수 있음을 표시한다. 연도를 넘는 일정과 윤일은 특히 확인한다.
- 미리 읽은 결과를 사용자가 추가한 후 월별 또는 전체 보기에서 검토하며, 전체 일정의 원본 대조 확인을 해야 다음 단계로 이동한다.
- 임의 보정으로 인쇄가 완료되었다고 판단하지 않는다. 주문/인쇄 절차는 이번 변경 범위가 아니다.
