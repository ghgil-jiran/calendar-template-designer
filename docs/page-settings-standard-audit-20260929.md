# 표준 탁상달력 페이지 설정 전수 조사 (2026-09-29)

범위: 에디터 Preview 브랜치의 260×180mm 탁상달력. 페이지 설정의 `구성 형태 → 포함 개체 → 대표 배치` 정의와, 저장 뒤 개체 배치 적용 경로를 조사했다. 화면에서 확인한 사례는 표지의 사진 개체 누락과 와이드형 월력 뒷면이다. 아래의 나머지 조합은 코드 대조 결과이며, 브라우저에서 각 조합의 저장·재열기·PDF를 전부 실행한 결과는 아니다.

## 전체 흐름에서 확인한 차이

1. 페이지 설정 저장은 표지·월력 앞면·뒷표지의 구성 정보를 저장하지만, 이 면의 편집 개체를 즉시 재배치하지 않는다. 개체 생성과 재배치는 AI 디자인 생성/초안 적용에서 `ACDLDesignLayoutApplication.apply`가 실행될 때 이뤄진다. 월력 뒷면은 구성 변경 시 `applyConfiguredMonthBackLayout`으로 즉시 12개월 개체를 재생성한다. 간지는 저장 시 물리 면의 용도만 반영한다.
2. 표지·뒷표지 설정을 열 때 `readPageSettings`가 저장된 개체 목록을 역으로 읽어 체크 상태를 덮어쓴다. 그래서 사진형이라는 설정과 실제 표지에 사진 개체가 없는 상태가 동시에 나타날 수 있다. 구성 형태를 다시 선택해도 표지의 사진을 자동 체크하지 않는다.
3. 대표 배치 미리보기의 좌표 정의와 실제 AI 배치 적용의 좌표 정의가 두 파일에 중복돼 있다. 월력 앞면은 특히 미리보기 달력 영역 `y=15%, h=80%`와 실제 배치 영역 `y=8%, h=87%`가 다르다. 표지·뒷표지에도 일부 좌표 차이가 있다. 미리보기만 보고 실제 결과를 보증할 수 없다.
4. 배치 계산은 대부분 고정된 페이지 백분율을 사용한다. 이 정의들은 `pageSize`나 재단면의 가로세로 비율을 입력받지 않으므로, 와이드형에 그대로 적용하면 개체의 실제 mm 크기와 배경의 여백 관계가 달라진다.

## 구성 형태별 목록

표의 `기본`은 새 설정/형태 전환 시 코드에 지정된 개체다. 이미 만든 템플릿에서는 실제 저장 개체와 다르게 표시될 수 있다. `즉시`는 페이지 설정 저장만으로 편집 화면에 반영되는지를 뜻한다.

**면 위치와 페이지 특성은 서로 다른 축이다.** 실제 면은 선택한 간지 매수와 앞·뒤 구성에 따라 표지 안쪽면, 앞 간지 앞면·뒷면, 뒤 간지 앞면·뒷면, 뒷표지 안쪽면으로 생긴다. 그 각각의 면에 학교 상징·학교 소개·연력·학사일정·Yearly Plan·사용자 정의·빈 페이지 중 하나를 선택한다. 따라서 아래의 일곱 줄은 특정한 ‘안쪽면 종류’가 아니라 **각 실제 면에 지정할 수 있는 페이지 특성별 설정**을 조사한 것이다. 첫 월력 뒷면을 다른 물리 면과 공유하는 옵션이 선택되면 실제 면 목록과 역할도 달라진다.

## 다음 수정 단계의 검증 기준

1. 각 형태에 **필수 개체**, 처음 선택할 **기본 개체**, 추가 가능한 **선택 개체**를 정의한다. 형태 변경 시 필수/기본값과 추천 배치를 함께 갱신하되 사용자가 이미 편집한 개체를 조용히 삭제하지 않는다.
2. 선택 개체에 따라 유효하지 않은 배치는 숨기거나 이유를 표시한다. 남은 카드들은 실제 위치 또는 표시 스타일이 구분돼야 한다. 미리보기는 실제 배치 계산의 결과를 그대로 보여준다.
3. 페이지 설정을 저장한 뒤 새 초안의 편집 화면과 재열기에서 개체 구성·좌표가 일치해야 한다. 기존에 수동 편집한 개체를 다시 생성할 때는 영향 범위를 표시한다.
4. 표준형 260×180mm부터 각 구성 형태·대표 배치의 대표 조합을 실제 편집 화면으로 확인한다. 그 다음 같은 규칙에 완성 규격과 가로세로 비율을 입력해 와이드형을 검증한다. 세로형은 별도 배치 방향을 설계한다.
5. 월력 개체의 최소 물리 크기, 안전 여백, 겹침, 페이지 밖 돌출과 12개월 적용을 검사한다. 표지·월력 앞/뒤·간지·뒷표지 및 저장·재열기·PDF 순으로 확인한다.
