# 인쇄 품질·공통 Runtime 통합 검증 계획

## 목표

템플릿 에디터에서 인쇄 품질까지 검증된 Template Package를 만들고, 사용자 서비스는 같은 Package와 같은 공통 Runtime에 학교 정보·사진·일정만 적용해 고객용 인쇄 파일을 완성한다.

한 템플릿의 화면을 임시로 맞추는 것이 완료 기준이 아니다. 템플릿 에디터가 만들 수 있는 페이지 구조·개체·스타일·자산 기능을 공식 지원 목록으로 관리하고, 에디터 화면·사용자 서비스·검토 PDF·인쇄 PDF에서 같은 결과가 나오는지를 자동 확인한다.

## 고정 원칙

- 템플릿의 페이지 구조와 인쇄 규격은 Template Package가 소유한다.
- 사용자 서비스는 페이지를 재구성하지 않고 사용자 Dataset만 바인딩한다.
- Master 상속, Binding, 자산 해석, 최종 좌표와 스타일 계산은 공통 Runtime에서 한 번만 수행한다.
- AI 배경은 임시 URL이 아니라 필수 여부·DPI·배치 규칙을 가진 Package 이미지 자산으로 저장한다.
- 지원하지 않는 페이지·개체는 생략하거나 기본 페이지로 대체하지 않고 검사 단계에서 명확히 중단한다.
- 운영 중인 Published Package와 Production은 자동으로 교체하지 않는다.

## 검증 기준

| 검사 단계 | 확인 내용 | 통과 결과 |
|---|---|---|
| 1. Package 계약 | ID·버전·SHA, 페이지 순서와 면수, 개체·스타일 지원, 자산·Binding | 지원하지 않는 기능과 필수 자산 누락 없음 |
| 2. Runtime 동등성 | 에디터 인쇄 모드, 사용자 서비스, 검토 PDF RGB | 페이지별 개체·좌표·스타일·크롭·Binding 일치 |
| 3. 인쇄 구조 | CMYK, ICC, K100, 폰트, Trim/Bleed, 재단선, PDF/X-4 | 자동 Preflight 통과 |
| 4. 실물 검증 | 색상, 작은 글자와 선, 사진 품질, 재단·제본 | 대표 조합 실물 승인 |

## 단계별 작업

### 0. 기준선 보존

- 현재 Template Editor Production, 작업 브랜치, Runtime 버전을 기록한다.
- 기존 사용자 서비스 PDF/X-4 변환 조건과 Ghostscript 설정은 출력 기준선으로 보존한다.
- 대표 검증용 템플릿은 서로 다른 페이지 구성 3개를 사용한다.

### 1. 기능 목록과 기본 검사

- 게시 후보 3개와 에디터 생성 기능에서 페이지 역할·개체·스타일·Binding·자산을 전수 추출한다.
- Runtime 지원 목록과 비교해 누락 기능을 오류로 표시한다.
- 템플릿 카드의 `인쇄·출력 품질 검사`에서 페이지 수, 개체 수, 기능 목록, 오류와 경고를 확인한다.
- 기능별 작은 검증 문서로 정상 조합과 실패 조합을 자동 시험한다.

### 2. 공통 중간 문서

- `Template Package + Dataset Snapshot`을 하나의 `Resolved Render Document`로 계산한다.
- 최종 페이지, Master 상속, Binding 결과, 자산 참조, 좌표·스타일, 화면/인쇄 표시 여부를 문서에 확정한다.
- 에디터와 사용자 서비스가 원본 Package를 각자 다시 해석하는 경로를 제거한다.

### 3. RGB 결과 동등성

- 전체 페이지를 에디터 인쇄 모드, 사용자 서비스, 검토 PDF RGB로 같은 크기의 PNG로 추출한다.
- 페이지별 누락 개체, 위치·크기, 글꼴·색·선·투명도, 이미지 크롭을 비교한다.
- 문제는 공통 Runtime, 에디터 연결부, 사용자 서비스 연결부, PDF 변환 중 실제 소유 위치에서 수정한다.

### 4. 인쇄 PDF 연결

- RGB 결과가 일치한 뒤 기존 MVP의 CMYK·ICC·K100·PDF/X-4 변환을 연결한다.
- 가변 면수, TrimBox/BleedBox, 0.540pt 재단선, 폰트와 전체 래스터화 여부를 자동 검사한다.
- 템플릿 에디터에는 Template Preflight, 사용자 서비스에는 사용자 데이터 적용 후 Document Preflight를 적용한다.

### 5. 세 템플릿과 변형 데이터

- 간지 유무, 26면/28면 이상, 서로 다른 월력 뒷면 구성을 포함한 3개 템플릿을 전체 페이지 검사한다.
- 긴 학교명, 일정 과다·없음, 이미지 누락·저해상도·서로 다른 비율을 시험한다.
- 새 기능이 발견되면 지원 목록, 렌더 구현, 자동 시험을 함께 추가한다.

### 6. Preview와 실물 승인

- Template Editor Preview에서 3개 카드 검사를 실행하고 결과를 보관한다.
- 사용자 서비스 Preview와 같은 Package ID·버전·SHA를 비교한다.
- 대표 조합을 실물 인쇄한 뒤 색상·선·작은 글자·재단 결과를 인쇄 규칙에 반영한다.
- 승인 전까지 Production Package는 변경하지 않는다.

## 사용자가 준비할 3개 템플릿 권장 조합

1. 26면, 간지 없음, 표지 안쪽면과 첫 월력 뒷면 공유
2. 28면 이상, 앞 간지 포함, 학교 상징·연력·월력 앞뒤 구성
3. 앞·뒤 간지 또는 복수 이미지 월력 뒷면, AI 배경과 다양한 편집 개체 포함

각 템플릿은 이름뿐 아니라 Package ID·버전·SHA와 기준 Dataset을 고정한다.

## 현재 구현 범위

첫 단계로 템플릿 카드에서 저장 문서를 직접 읽어 페이지 역할·개체·스타일·Binding·이미지 자산·면수·도련 선언을 검사한다. 이 결과는 이후 화면 비교, RGB PDF, CMYK/PDF-X 검사를 같은 창에 추가하기 위한 시작점이다.
