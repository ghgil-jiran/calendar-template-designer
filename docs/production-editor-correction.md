# 접수본을 템플릿 에디터에서 교정

2026-10-04 Preview 작업. Production 변경 없음.

제작 검수 1단계에서 검수를 시작한다. 3단계의 ‘템플릿 에디터에서 교정’으로 접수 건 전용 에디터를 연다. 왼쪽에서 면을 선택하고 기존 개체의 위치·크기·문자열·이미지를 수정한다. 새 JPEG/PNG/WebP 원본은 기존 private 교정 원본 보관소에 업로드한다. 변경 기록을 입력하고 ‘새 교정 버전 저장’을 누른다. 재진입하면 최신 저장본을 연다.

접수 당시 정확한 templateId/version 패키지의 SHA-256과 프로젝트 형식을 확인한다. 원본 프로젝트 구조를 사용하되 접수 Runtime의 각 면·개체와 동결된 사용자 입력·이미지를 적용한다. 원본 템플릿 게시/저장 API는 사용하지 않는다. 새 개체 생성·면 추가·규격 변경은 현재 지원하지 않는다. 패키지 누락 또는 면/규격 불일치면 복원을 중단하며 최신 템플릿으로 대체하지 않는다.

기존 calendar_production_revisions.document에 Runtime 문서와 editorProject를 함께 보관한다. 서버가 신뢰한 직전 버전 기준으로 Runtime 문서를 다시 계산한다. 접수 snapshot과 이전 교정본을 수정하지 않는다. 이번 변경에 추가 SQL은 없다.

‘저장 버전 인쇄 품질 검사’는 저장한 교정 버전만 기존 에디터 검사 화면으로 전달한다. 검사 패키지 ID는 production-{revision UUID}이며 교정본 해시를 패키지 프로젝트에 보관한다. 보관 이미지의 임시 URL을 검사 패키지 생성 전에 실제 바이트로 동결한다. 네이티브 인쇄 정의가 없는 프로젝트는 최종 출력 패키지 생성을 막는다. 새 교정 버전은 이전 검사 패키지나 인쇄 승인을 계승하지 않는다.

이 연결은 최종 승인·인쇄소 전달을 구현한 것이 아니다. 실제 관리자 로그인 상태의 접수본 복원 → 교체 → 저장 → 재진입과 CMYK Worker의 최종 PDF/X-4 산출물 검증이 필요하다. 인쇄 정의·CMYK 이미지 원본 부족 등 기존 검사 차단 조건은 그대로 적용한다. 미리보기 일치로 출력 성공을 판단하지 않는다.
