## 2026-09-03 — Master Admin 로그인 전환

- 공개 랜딩과 이메일·비밀번호 로그인 화면을 추가하고 기존 원격 접근 코드 입력 흐름을 제거했다.

- 배포 환경에는 기존 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`가 필요하며 `TEMPLATE_EDITOR_ACCESS_TOKEN`은 더 이상 사용하지 않는다.
- 배포 전 `202609030001_template_master_admin.sql` 적용과 Supabase Authentication 계정·Master Admin 행 등록이 필요하다.
- 다수 관리자 초대·역할 구분·계정 관리 화면은 후속 범위다.

## 문서 사용법

이 문서는 채팅 요약이 아니라 새 채팅이 작업을 이어받기 위한 정본이다. 새 채팅을 시작하기 전 현재 채팅에서 업데이트하고 GitHub에 저장한다. 새 채팅은 기억이나 이전 답변만 믿지 않고 이 문서와 연결된 설계 문서를 먼저 확인한다.

## 새 채팅 전환 절차

### 1. 현 채팅에서 전환 준비

새 채팅으로 넘어가기 전에 다음을 현 채팅에 요청한다.

> 다음 채팅으로 이어갈 수 있도록 현재 상태, 확정된 결정, 안정 코드 기준, 다음 할 일, 변경 금지 항목을 핸드오프 문서에 정리하고 GitHub에 저장해줘. 새 채팅 시작 문구도 만들어줘.

현 채팅은 다음을 완료해야 한다.

1. 현재 완료 상태와 미완료 상태를 구분한다.
2. 최근 안정 코드·테스트·배포 기준을 기록한다.
3. 다음 작업의 정식 설계 문서를 연결한다.
4. 시행착오와 다시 사용하면 안 되는 접근을 기록한다.
5. 다음 채팅의 첫 작업을 한 가지로 명확히 적는다.
6. 관련 문서를 GitHub에 저장하고 커밋을 확인한다.

### 2. 새 채팅 시작

새 채팅의 첫 메시지로 아래 문구를 사용한다.

```text
이전 학사달력 프로젝트 작업을 이어갈게.

작업하기 전에 다음 자료를 순서대로 확인해줘.
1. 저장소의 AGENTS.md와 지시된 시작 문서
2. docs/integration/HANDOFF.md
3. HANDOFF.md에 연결된 현재 최우선 설계 문서
4. HANDOFF.md에 기록된 안정 코드와 테스트 기준

먼저 현재 상태, 확정된 결정, 다음 첫 작업, 변경하면 안 되는 항목을 짧게 정리해서 알려줘.
확인 전에는 코드를 수정하거나 배포하지 말고, 내가 “진행해”라고 하면 다음 첫 작업부터 시작해줘.
```

월력 디자인 프리셋 작업을 이어갈 때는 새 채팅이 반드시 [`월력 디자인 프리셋 시스템`](../architecture/MONTHLY-CALENDAR-PRESET-SYSTEM.md)을 읽어야 한다.

### 3. 새 채팅의 인수 확인

새 채팅은 작업 전에 최소한 다음 내용을 정확히 말할 수 있어야 한다.

- 현재 Production이 어떤 안정 상태인지
- 다음 최우선 작업이 무엇인지
- 샘플 3번과 6번을 어떻게 구분하는지
- 5×7·6×7이 디자인이 아니라 날짜 배치 구조라는 점
- 초기 목표가 완성 프리셋 5~6종이라는 점
- 내부 요소 자유 배치는 현재 범위가 아니라는 점
- 사용하지 않을 접근이 무엇인지

하나라도 다르게 이해하면 작업을 시작하지 않고 문서를 다시 확인한다.

### 4. 새 채팅이 잘못 시작된 경우

새 채팅이 이전 결정을 놓치거나 잘못된 기준으로 작업하려 하면 그 채팅에서 계속 보정하지 않는다. 아직 열려 있는 이전 채팅으로 돌아와 다음과 같이 요청한다.

> 새 채팅이 핸드오프 내용을 정확히 이어받지 못했어. 현재 정본과 새 채팅의 잘못 이해한 부분을 비교해서 HANDOFF.md와 시작 문구를 다시 정리하고 GitHub에 저장해줘.

그다음 새 채팅에 수정된 시작 문구를 다시 전달한다. 이미 잘못 수정된 코드가 있다면 먼저 변경 범위와 안정 기준을 비교하고, 승인 없이 자동 병합하거나 광범위하게 되돌리지 않는다.

### 5. 전환 완료 조건

다음 조건이 모두 충족되면 현 채팅의 역할이 끝난다.

- 핸드오프 문서가 최신 상태다.
- 관련 설계 문서가 연결돼 있다.
- GitHub 저장 커밋이 확인됐다.
- 새 채팅 시작 문구가 준비됐다.
- 새 채팅이 현재 상태와 다음 첫 작업을 정확히 설명했다.

## 이전 상태 기록 — 월력 프리셋 도입 당시

Project 1은 학사달력 템플릿 구조와 Designer Studio를 마감하고 GitHub에 배포하기 위한 단계다.

2026-09-02 기준 다음 최우선 작업은 [`월력 디자인 프리셋 시스템`](../architecture/MONTHLY-CALENDAR-PRESET-SYSTEM.md)이다. 월력을 고정 표로 보정하는 작업을 중단하고 날짜 계산과 표현 프리셋을 분리한다.

현재 Production은 잘못된 SVG 격자 레이어를 제거한 안정 상태다. 코드 기준은 `51665c2`, 회귀검사 기준은 `e59321d`다.
