# schoolp 도메인 참고자료 (as-is)

기존 schoolp(우리학교인쇄) 서비스의 실제 코드베이스를 분석한 **as-is 스냅샷**입니다.
schoolp 기존 사업 도메인(주문/디자인/견적/상담 등)과 관련된 프로젝트를 기획·개발할 때,
"현재 시스템이 어떻게 되어 있는가"를 참고하는 용도입니다.

분석 원본: `schoolp-api`(PHP/Slim3 백엔드), `schoolp-web`(Vue2 고객), `schoolp-admin-unified`(React 관리자).

## ⚠️ 이 문서의 위치 (반드시 읽을 것)

- **스타터 표준이 아닙니다.** 이 폴더는 schoolp 레거시 도메인 지식일 뿐, `AI_START_HERE.md`·`docs/COLLABORATION_MODEL.md` 같은 스타터 개발 표준과 성격이 다릅니다.
- **API 계약이 아닙니다.** 여기 적힌 레거시 엔드포인트·필드·상태값(enum)을 **실제 연동 대상이나 계약으로 삼지 마세요.** 스타터의 목 계약 우선 원칙(`/api/*` 목 route + `src/lib/api/contracts.ts` 공유 계약, 공식 문서 없으면 실연동 금지)은 그대로 적용됩니다. 이 문서는 그 계약 초안을 **설계할 때 참고하는 도메인 지식**입니다.
- **신규 서비스의 자체 계약이 우선입니다.** 새 서비스의 화면 흐름, `/api/*` 목 계약, Supabase migration/seed는 그 서비스의 요구사항으로 새로 설계합니다. 이 폴더의 테이블·컬럼·enum을 그대로 복사하거나 새 서비스 구조를 레거시 DB에 맞춰 축소하지 마세요.
- **제약이 아니라 참고자료입니다.** 상태값·구조는 개선 작업에서 바뀔 수 있습니다. 새 설계를 레거시 enum에 억지로 맞추지 마세요. 이 문서는 기존 데이터 마이그레이션과 기존 화면·API 접점을 판단하는 기준점으로만 쓰세요.
- **무관한 프로젝트라면 무시/삭제해도 됩니다.** schoolp 주문/디자인 도메인과 상관없는 프로젝트라면 이 `docs/domain/` 폴더는 필요 없습니다.
- **정본 위치:** `schoolp-ai-start` 저장소. 레거시 코드가 바뀌면 그곳에서 갱신되며, 이 사본은 스타터 배포 시점의 스냅샷입니다.

## 읽는 순서

- 처음 보는 경우: 01 → 02 → 07
- 특정 기능 기획 시: 02의 관련 도메인 → 07의 실제 스키마 확인 → 각 프로젝트 상세(03~05)
- 기획 브레인스토밍(`docs/PLANNING_ELICITATION.md`) 전에 02·07을 먼저 읽으면 서비스 언어로 질문하기 쉬워집니다.

## 신규 서비스에서 쓰는 법

1. 먼저 이 문서로 기존 용어와 업무 흐름을 이해합니다.
2. 실제로 필요한 데이터는 새 서비스 요구사항에서 다시 묻고, `src/lib/api/contracts.ts`의 목 계약으로 정의합니다.
3. 저장이 필요한 기능만 Supabase Postgres로 최소 구현합니다. 이때 Supabase schema는 동작하는 요구사항 명세이며, 운영 DB 설계 확정본이 아닙니다.
4. 기존 schoolp 데이터가 필요하면 직접 DB 접근이 아니라 공식 API 계약으로 연동합니다. 공식 계약이 없으면 목 route로 개발하고 `HANDOFF.md`에 개발자 확인 항목으로 남깁니다.
