# 제작 검수 접수 연결 — 2026-10-03

## 구현
- 사용자 서비스 제작 전 확인: 저해상도 경고를 동의 후 진행하도록 변경. 검사 불가/원본 읽기 오류는 접수 전 해결 필요.
- 담당자 이름 및 이메일/전화번호 중 하나 필수. 접수 실패를 완료로 표시하지 않음.
- 편집 문서, 실제 배치 확대값이 반영된 공통 Runtime document, printProfile, live store bundle, 이미지 검사 및 사용자 동의 내용을 접수 시점 JSON 사본으로 저장.
- 사용자/템플릿 이미지 원본은 별도 비공개 버킷에 복사하고 이미지 내용 기반 식별자로 저장. 성공한 원본 복사 없이 접수 생성 불가.
- 사용자 인증 및 calendar_docs.owner_id 검사. 접수 ID 재시도는 같은 번호 반환.
- 관리자 API는 기존 Master Admin 인증 적용. 접수 목록 검색/상태 필터/50건 단위 조회, 상세 연락처/템플릿 버전/검사/동의/원본 링크/접수 데이터 다운로드.
- DB trigger는 접수 snapshot 및 신원·연락처·접수일 변경 금지. 사용자의 후속 편집은 접수본을 바꾸지 않음.

## 적용
공유 Supabase SQL Editor에서 `supabase/migrations/202610030001_calendar_production_requests.sql`을 1회 실행한다. 기존 탁상형 기본값 SQL과 다른 새 마이그레이션이다. 서비스 서버에는 기존 SUPABASE_SERVICE_ROLE_KEY/NEXT_PUBLIC_SUPABASE_URL, 에디터에는 기존 SUPABASE_URL/SUPABASE_SERVICE_ROLE_KEY 사용. 두 서비스가 동일 DB를 사용하는지 확인한다.
Preview 배포 후 사용자 접수→번호 표시→관리자 로그인→제작 검수 목록/상세를 확인한다. 사용자가 SQL 실행 완료를 확인했다. 실제 DB/Storage/RLS를 통한 전체 접수 검증은 아직 실행하지 않았다.

## 보류
- 이번 접수는 고정 편집 데이터/공통 Runtime 및 원본 이미지 보관이다. 사용자 브라우저에서 별도로 저장한 모양 확인용 PDF 파일 자체를 자동 업로드하지 않는다.
- 접수본에서 동일 Runtime으로 확인 PDF를 다시 생성하는 화면, 에디터 교정본 열기, CMYK/worker 검사 및 인쇄소 전송은 미연결.
- 결제, 수량/단가, 관리자 상태 변경/원본 재요청 발송은 미구현. 상세 연락처와 원본으로 관리자가 판단 가능.
- 사용자 동의는 인쇄 품질 승인과 다름. 자동 검사 결과는 사용자 셀프 체크 기록으로 보관하며 관리자 최종 승인으로 취급하지 않음.
- 미완료 업로드 폴더 정리, 사용자 접수 이력 화면, 보관기간 정책은 후속.

## 검증
서비스 관련 테스트 20개 및 관리자 API 3개 통과. 두 프로젝트 최종 빌드 통과. 실제 로그인/접수/관리자 조회 E2E, DB 마이그레이션은 사용자 실행 완료 확인. Production 변경 없음.
