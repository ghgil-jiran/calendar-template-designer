# 탁상형 확대 인쇄 출력

- 원본 편집 규격: 260×180mm. 원본 템플릿과 기본형 CMYK PDF는 변경하지 않는다.
- 확대형: 가로 297mm, 세로 180×297/260=205.615384615…mm. 화면·파일명은 205.615mm로 표시한다.
- 균등 배율: 297/260. 최종 사방 도련 3mm, 재단선은 목표 규격에서 새로 생성한다.
- 5단계 ‘출력 규격·최종 확인’에서 확대형을 선택하고 ‘확대 PDF 생성·검사’를 요청한다.
- 기존 로컬 워커 저장소 `ghgil-jiran/-v1.1`의 해당 기능 브랜치를 갱신한 뒤 표시된 `--job` 명령으로 실행한다. 원본 CMYK 재변환·브라우저 재렌더는 하지 않는다.
- 원본 완료 잡 ID·패키지 SHA에 묶인 별도 잡/PDF/검사 결과를 저장한다. 확대 잡은 원본 검사 이력을 대체하지 않는다.
- 이미지·ICC·압축·마스크 보존, 페이지 수, PDF 박스, PDF/X·CMYK·K100·벡터 구조를 검사한다. 확대 후 이미지 사용 위치의 유효 DPI를 재측정하고 기준 미달·미지원 구조는 확인 필요로 기록한다. 원본 수동 비교·육안 승인 결과를 확대본 통과로 복사하지 않는다.
- Preview는 인쇄 API의 새 Preview와 함께 연결해야 한다. `USER_SERVICE_PRINT_PREFLIGHT_API_URL`은 해당 Preview 브랜치에만 설정한다. Production 변경은 별도다.

검증: 확대 PDF 및 API 테스트 8개, 원본/확대 이력 분리 2개 통과. 실제 고객 28면 PDF·로컬 워커·관리자 인증을 포함한 통합 검증은 별도다. 전체 에디터 빌드에는 수정 전에도 재현되는 기존 실패 항목이 남아 있다.

## 2026-11-13: 확대 요청 진단과 화면 안내

- 기본 작업의 `status: done`과 서버의 `report.verified: true`는 별개다. 확대 API도 최종 검증 승인이 없는 원본을 409로 거부한다. UI에서 이를 우회하지 않는다.
- 버튼 비활성화 사유, 원본 검사 상태 다시 확인, 요청 실패 메시지·HTTP 상태·오류 코드를 출력 규격 영역에 유지한다.
- 요청 응답의 새 작업 ID·sourceJobId·outputProfile·상태를 확인한 경우만 명령을 표시한다. `--once` Worker는 확대 작업의 새 ID로 다시 실행해야 한다.
- 대기·처리·실패·확인 필요·완료 상태를 현재 단계와 상단 카드에 반영한다. 확대 미생성 상태를 검사 완료로 표시하지 않는다. 상태 조회 통신 실패도 작업 ID를 유지한 채 화면에 표시한다.
- 회귀 검사: 검증 미승인 원본, 409 요청 실패, 정상 새 작업 명령, 잘못된 응답, 중복 클릭, 원본 상태 갱신, 확대 확인 필요 상태. 실제 샘플 D 서버 보고서와 관리자 로그인 상태의 버튼 실행은 별도 확인이 필요하다.

## 확대본 재생성

완료된 확대본에서 ‘확대 PDF 다시 생성·검사’를 누르면 force=true로 새 작업을 요청한다. 기본 PDF와 이전 확대본 이력은 유지한다. 같은 조건의 queued/processing 작업이 있으면 중복 생성 대신 해당 작업을 반환한다. 기존 API가 완료 결과를 다시 반환하면 화면에 API 연결 오류를 표시한다. 새 API와 Editor Preview의 브랜치별 연결 설정을 함께 배포해야 한다.

## 재검사 작업 상태 표시

2026-11-13: 작업 응답의 createdAt/updatedAt/completedAt을 보존하며, 기본 PDF는 작업 생성 시각을 우선해 선택한다. 재검사 요청에서 받은 작업 ID를 추적하고 이력 반영이 늦으면 같은 ID의 상태를 직접 조회한다. 이전 완료 결과로 되돌리지 않는다. 템플릿 전환 또는 새 요청보다 먼저 시작된 지연 응답은 무시한다.
