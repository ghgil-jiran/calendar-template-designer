# 월력 디자인 프리셋 시스템

- 문서 상태: 제품 방향 확정 · 구현 설계 대기
- 작성일: 2026-09-02
- 우선 대상: 달력 템플릿 에디터의 탁상형 학사달력
- 참고 샘플: 샘플 3번, 샘플 6번

## 1. 다음 최우선 작업

달력 템플릿 에디터의 월력을 고정된 표가 아니라 **날짜 계산 위에 완성된 디자인 프리셋을 적용하는 반복 디자인 시스템**으로 재정의한다.

첫 완료 목표는 월력 내부 요소를 자유 배치하는 편집기가 아니다. 검증된 월력 디자인 5~6종을 제공하고, 템플릿 디자이너가 프리셋을 선택한 뒤 허용된 스타일만 조정해 사용자용 템플릿을 완성하는 것이다.

사용자는 월력 프리셋을 직접 설계하지 않는다. 디자이너가 완성한 템플릿 카드와 미리보기를 보고 사용할 템플릿을 선택한다.

## 2. 확정된 제품 원칙

1. 월력은 엑셀과 같은 고정 표가 아니다.
2. 5×7·6×7은 디자인이 아니라 날짜를 배치하는 논리 구조다.
3. 날짜 계산과 날짜 표현을 분리한다.
4. 샘플 3번과 샘플 6번은 한 표에서 선을 숨긴 변형이 아니라 서로 다른 표현 프리셋이다.
5. 초기에는 완성된 디자인 프리셋 5~6종을 제공한다.
6. 모든 초기 프리셋은 5행×7열과 6행×7열을 모두 지원한다.
7. 일정량 때문에 월력 전체 높이 또는 행 수가 변하지 않는다.
8. 미니 월력은 모든 프리셋에서 사용할 수 있지만 기본 표시 여부와 표현은 프리셋이 결정한다.
9. 월력 내부 텍스트·도형·선을 자유롭게 배치하는 기능은 장기 후속 범위이며 초기 구현에 포함하지 않는다.
10. 화면, 미리보기, 사용자 서비스, PDF는 같은 프리셋 계약과 같은 계산 결과를 사용한다.

## 3. 월력의 네 계층

| 계층 | 책임 | 디자인에서 분리할 내용 |
|---|---|---|
| 날짜 계산 | 연·월, 시작 요일, 5·6주, 이전·다음 달 날짜 위치 계산 | 색상, 선, 글꼴, DOM |
| 월력 영역 | 월 제목·요일·날짜 영역의 비율과 전체 크기 결정 | 개별 일정 데이터 |
| 표현 프리셋 | 날짜 칸 모양, 선, 간격, 월 제목, 요일, 일정 표현, 미니 월력 스타일 | 실제 날짜 계산 |
| 콘텐츠 정책 | 공휴일·기념일·음력·24절기·단일 일정·기간 일정의 표시 여부와 우선순위 | 월력 외형 |

날짜 계산 결과는 프리셋과 관계없이 동일해야 한다. 프리셋을 바꿔도 같은 날짜와 일정이 다른 모습으로 표현될 뿐 데이터가 이동하거나 사라지면 안 된다.

## 4. 초기 프리셋 계열

명칭은 구현 과정에서 조정할 수 있지만 서로 다른 표현 구조로 관리한다.

| 프리셋 | 기준 | 핵심 표현 | 일정 공간 |
|---|---|---|---|
| 학사일정 박스형 | 샘플 6 계열 | 사각 날짜 칸, 가로·세로 경계, 일정 막대 | 높음 |
| 끊어진 가로선형 | 샘플 3 계열 | 세로선 없음, 날짜 칸마다 독립된 밑줄 | 중간~높음 |
| 열린 주간선형 | 신규 | 주 단위 가로 구분, 열린 좌우 영역 | 높음 |
| 둥근 카드형 | 신규 | 날짜별 둥근 배경 또는 카드 | 중간 |
| 미니멀 무선형 | 신규 | 선 없이 정렬과 여백으로 구분 | 낮음~중간 |
| 날짜 포인트형 | 신규 | 날짜를 원 또는 포인트 도형으로 강조 | 낮음~중간 |

프리셋별 임시 렌더러를 복사하지 않는다. 공통 날짜 계산 결과와 공통 프리셋 계약을 사용하고, 프리셋은 허용된 토큰과 표현 방식의 차이만 가진다.

## 5. 5×7·6×7 규칙

- 5×7은 날짜 영역을 5개의 동일한 주 행과 7개의 요일 열로 나눈다.
- 6×7은 같은 날짜 영역을 6개의 동일한 주 행과 7개의 요일 열로 나눈다.
- 월력 전체 높이, 월 제목 영역, 요일 영역, 날짜 영역은 템플릿이 정한 비율을 유지한다.
- 5행과 6행 전환 시 날짜 행 높이, 내부 여백, 일정 글자와 막대 높이를 프리셋 정책에 따라 다시 계산한다.
- 행 수 변경으로 월 제목이 밀리거나 월력 영역과 겹치면 안 된다.
- 특정 행 수에서만 정상인 프리셋은 등록 또는 발행 검사를 통과할 수 없다.

## 6. 미니 월력 규칙

- 모든 프리셋은 미니 월력 기능을 지원할 수 있다.
- 프리셋은 기본 표시 여부, 글꼴, 여백, 배경, 선 표현을 가진다.
- 디자이너는 템플릿에서 표시 여부를 선택할 수 있다.
- 현재 월에 사용되지 않는 연속 위치가 3칸 이상 있을 때 바깥쪽 2칸을 미니 월력에 사용할 수 있다.
- 뒤쪽 공간을 먼저 확인하고, 부족하면 앞쪽 공간을 확인한다.
- 공간이 없으면 날짜 칸을 축소하거나 침범하지 않고 미니 월력을 숨긴다.
- 미니 월력은 보조 콘텐츠다. 부모 날짜 배치, 행 높이, 외부 선을 변경하지 않는다.
- 카드형·원형·무선형 프리셋은 디자인에 따라 미니 월력을 기본으로 숨길 수 있다.

## 7. 콘텐츠 밀도 정책

프리셋은 외형뿐 아니라 안전하게 표시할 수 있는 콘텐츠 밀도를 선언한다.

| 항목 | 정책 예시 |
|---|---|
| 날짜 | 필수, 위치·정렬·크기 지정 |
| 공휴일 | 표시 여부, 색상, 짧은 이름 사용 여부 |
| 기념일 | 표시 여부와 공휴일 다음 우선순위 |
| 음력 | 표시 주기 또는 숨김 |
| 24절기 | 표시 여부와 보조 글자 스타일 |
| 단일 일정 | 최대 줄 수, 줄 높이, 초과 표시 |
| 기간 일정 | 막대 높이, 최대 lane, 주 경계 분할 |
| 인접 월 날짜 | 숨김·연하게·보통 표시 중 선택 |

학사일정 박스형은 정보 밀도를 가장 높게 지원한다. 미니멀·포인트형은 표시 항목을 줄이되, 템플릿이 필수로 선언한 정보가 조용히 사라지면 안 된다. 표시 한도를 넘으면 숨김 개수 또는 경고를 제공한다.

## 8. 디자이너가 초기 단계에서 조정할 수 있는 값

- 프리셋 선택
- 월 제목 형식·정렬·기본 크기
- 글꼴과 글자색
- 일요일·토요일·공휴일 색상
- 날짜 크기와 정렬
- 셀 안쪽 여백과 셀 사이 간격
- 선 색상·굵기·길이·모서리
- 배경색과 둥근 모서리
- 일정 글자 크기·막대 높이·표시 개수
- 미니 월력 표시 여부와 프리셋이 허용한 스타일
- 5행·6행 또는 자동 행 모드

초기 단계에서 조정할 수 없는 값:

- 날짜 칸 내부 요소의 자유 이동
- 날짜 칸마다 서로 다른 임의 구조 작성
- 월력 내부에 임의 도형·텍스트를 반복 규칙 없이 삽입
- 날짜 계산 결과를 수동 좌표로 덮어쓰기

## 9. 계약 초안

이 구조는 구현 전 공통 계약으로 확정하고 Studio와 Runtime이 함께 사용해야 한다.

```json
{
  "calendarLayout": {
    "rowsMode": "fixed-5 | fixed-6 | adaptive",
    "columns": 7,
    "weekStartsOn": "sunday",
    "regions": {
      "titlePercent": 10,
      "weekdayPercent": 4,
      "dateGridPercent": 86
    }
  },
  "calendarPreset": {
    "presetId": "academic-boxed",
    "presetVersion": "1.0.0",
    "supportedRows": [5, 6],
    "cellPresentation": {},
    "titlePresentation": {},
    "weekdayPresentation": {},
    "eventPresentation": {},
    "miniCalendarPresentation": {},
    "contentPolicy": {},
    "editableTokens": []
  },
  "calendarOverrides": {}
}
```

`calendarOverrides`에는 프리셋이 허용한 값만 저장한다. 프리셋 원본과 사용자 조정값을 합친 결과는 Runtime이 계산하며 원본 프리셋을 직접 변경하지 않는다.

## 10. 구현 순서

### 1단계 — 현재 기준선과 계약 고정

- 롤백된 안정 렌더링을 기준으로 유지
- 샘플 3번·6번의 월 제목·요일·날짜·선·일정·미니 월력 치수 측정
- 날짜 계산 결과와 표현 프리셋 계약 분리
- 기존 `design.presetId`와 스타일 값을 새 계약으로 읽는 호환 계층 작성

### 2단계 — 샘플 6 박스형

- 5행·6행 동일 영역 검증
- 모든 날짜 칸의 선과 일정 공간 검증
- 공휴일·기념일·음력·절기·단일·기간 일정 과밀 검사
- 미니 월력 표시와 숨김 검증

### 3단계 — 샘플 3 끊어진 가로선형

- 박스형의 선을 숨겨 재사용하지 않고 독립 프리셋으로 구현
- 셀별 밑줄 길이와 간격을 프리셋 토큰으로 관리
- 세로선이 없어도 날짜 열과 일정 범위가 정확히 유지되는지 검증

### 4단계 — 추가 프리셋

- 열린 주간선형
- 둥근 카드형
- 미니멀 무선형
- 날짜 포인트형

각 프리셋은 하나씩 추가하고 12개월·5행·6행·화면 크기·미리보기·PDF 검사를 통과한 뒤 다음 프리셋으로 진행한다.

### 5단계 — 디자이너 선택 화면

- 프리셋 썸네일 5~6종 제공
- 선택 즉시 현재 월과 대표 5행·6행 월 미리보기 제공
- 조정 가능한 스타일만 Inspector에 노출
- 12개월 공통 적용과 월별 허용 override 구분

## 11. 수용 기준

1. 모든 프리셋이 5행과 6행에서 날짜 영역을 벗어나지 않는다.
2. 월 제목·요일·날짜 영역이 브라우저 크기에 따라 겹치지 않는다.
3. 날짜와 일정의 위치는 프리셋을 바꿔도 동일한 날짜 계산 결과를 따른다.
4. 이전·다음 달 날짜의 투명도가 선·배경·인접 셀에 영향을 주지 않는다.
5. 미니 월력 표시 여부가 부모 날짜 칸 크기와 월력 선을 바꾸지 않는다.
6. 샘플 3번의 선형 디자인과 샘플 6번의 박스형 디자인이 각각 독립적으로 재현된다.
7. 공휴일·기념일·음력·절기·단일·기간 일정의 표시 정책이 저장·재열기 후 유지된다.
8. 일정 초과가 조용히 잘리거나 월력 높이를 바꾸지 않고 경고 또는 초과 개수로 표시된다.
9. Studio·사용자 서비스·미리보기·PDF가 같은 프리셋 버전과 결과를 사용한다.
10. 12개월 대표 캡처와 샘플 PDF 비교를 통과해야 발행할 수 있다.

## 12. 사용하지 않을 접근

- 흐린 선 하나를 고치기 위해 월별·셀별 CSS 예외를 계속 추가하지 않는다.
- 박스형에서 일부 테두리만 숨겨 모든 디자인을 만들지 않는다.
- 실제 날짜 셀과 별개인 거대한 SVG 격자를 월력 위에 덮지 않는다.
- 일정 개수에 따라 날짜 행 또는 월력 전체 높이를 늘리지 않는다.
- 프리셋마다 날짜 계산과 일정 배치 코드를 복사하지 않는다.
- 화면에서만 맞고 미리보기·PDF에서 다른 치수를 사용하지 않는다.
