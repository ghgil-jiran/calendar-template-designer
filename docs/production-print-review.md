# 제작 검수 4단계: 기존 인쇄 검사 연결

2026-10-05 Preview 구현. Production 변경 없음. 이 문서는 기존 교정·인쇄 경로 문서의 ‘연결 전’ 설명을 대체한다.

## 관리자 흐름

3단계에서 교정하고 새 버전을 저장한 뒤 제작 검수로 돌아온다. 4단계는 최신 저장 버전 ID를 고정한다. 화면 준비 중 최신 버전이 바뀌면 재진입을 요청한다. 준비 후 검사는 표시한 버전에 고정되며, 새 버전을 검사하려면 4단계에 다시 진입한다.

1. 빠른 검사: 기존 TemplatePrintPreflight 및 화면·RGB 비교 모듈로 문서와 전체 면을 검사한다. 공통 에디터 렌더러로 복합 이미지 사용 영역을 측정한다. 사용 이미지 디코딩과 원본 바이트·헤더·SHA-256·배치 해상도를 확인한다. PDF 작업은 생성하지 않는다.
2. 오류를 해결하고 경고를 확인한다. 교정이 필요하면 3단계에서 새 버전을 저장하고 다시 검사한다. 빠른 검사 결과는 JSON으로 내려받을 수 있으며, 최종 요청에는 버전·문서 해시에 연결된 관리자 제출 검사 요약과 경고 확인을 기록한다. 이 요약 자체는 서버 자동 검사나 최종 승인이 아니다.
3. 최종 인쇄 PDF 생성·검사: 서버가 저장된 editorProject와 해당 접수의 원본만 사용해 비공개 입력을 동결한다. 기존 template_print_preflight_jobs 대기열에 기존 rendererId와 kind를 사용해 요청한다. 새 이미지 Worker나 ImageMagick을 사용하지 않는다.
4. 기존 사용자 서비스 폴더에서 갱신된 scripts/pdf-worker.mjs를 사용한다. 기존 Ghostscript·Inkscape·qpdf 경로를 그대로 실행한다. 화면에 표시한 `npm.cmd run pdf:worker -- --job <작업 ID>`로 해당 작업만 처리할 수 있다. Preview 보호가 있다면 기존 공유 URL/보호 설정을 해당 Editor Preview에 맞춰 사용한다. 새로운 프로그램 설치는 필요하지 않다.
5. 상태를 자동 갱신하고 완료 PDF를 다운로드해 교정 내용과 전체 면을 확인한다. 최종 승인과 전달은 별도의 5단계이며 아직 연결하지 않았다.

## 버전·원본·보안

- `production-{revision UUID}@1.0.0`은 검사 입력 전용 draft Package다. 사용자 템플릿 목록은 published/review만 조회하므로 이 자료를 게시하거나 노출하지 않는다. 공개 bucket에서는 준비를 중단한다.
- 접수 원본·기존 템플릿·교정 버전은 수정하지 않는다. 사용자/ready 교정 원본의 실제 바이트와 템플릿 패키지 SHA-256을 확인하고 사본을 private template-packages에 보관한다. 기존 파일을 덮어쓰지 않는다.
- 입력에는 requestId/revisionId/documentHash/contentHash/인쇄 계약/PDF 파이프라인 버전을 기록한다. 과거 템플릿의 승인·미리보기·검사 결과를 교정본 승인으로 계승하지 않는다.
- 기존 공통 renderPage의 교정 월별 달력 처리를 Worker에서도 사용한다. 동결한 프로젝트를 자동 마이그레이션하거나 배경을 검토용 저해상도 JPEG로 바꾸지 않는다. 교정된 투명도·필터도 원래 렌더 결과를 유지한다.
- 교정 원본 렌더 API는 작업별 Worker 접근 토큰을 요구한다. 토큰은 대기열 private payload에만 보관하고 사용자에게 반환하지 않는다. Worker는 해당 Editor origin 요청에만 헤더를 붙이며 외부 원본 URL에는 전달하지 않는다.
- 새 SQL은 없다. 기존 교정 버전·원본 테이블, template_packages, template_print_preflight_jobs, 비공개 보관소를 사용한다. 과거 이미지 Worker SQL 권한을 복원하지 않는다.

## 재사용과 검증 한계

같은 버전·입력 SHA·Editor origin·출력 계약으로 실행 중인 작업은 재사용한다. 완료·자동 검사 통과·해당 파이프라인과 버전 정보가 일치하고 파일이 존재하면 완료 결과를 재사용한다. ‘다시 생성’은 이전 결과를 남기고 새 작업을 생성하며 실행 중 작업을 강제로 중단하지 않는다. 변경하지 않은 개체/면을 이전 템플릿의 결과에서 가져오는 최적화는 없다.

자동 테스트는 원본 동결·버전 연결·비공개 상태·작업 재사용·접근 제한·화면의 생성 요청 조건을 확인한다. 로그인한 실제 접수본의 빠른 검사와 사용자 PC Worker의 30면 최종 생성·PDF/X-4 완주는 별도의 실제 검증이 필요하다. 미리보기나 Preview READY만으로 CMYK 성공을 판단하지 않는다.
