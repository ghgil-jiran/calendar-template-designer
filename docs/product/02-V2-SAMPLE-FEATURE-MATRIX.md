# ACDL v2 탁상형·벽보형 샘플 기능 매트릭스

- 문서 상태: Draft 1
- 작성일: 2026-08-05
- 대상 제품: 학사달력 에디터 서비스
- 지원 상품 범위: 탁상형 달력, 벽보형 달력

## 1. 문서 목적

이 문서는 실제 학사달력 샘플에서 확인된 기능을 기준으로 ACDL v2의 제품 지원 범위를 정의한다. 디자인 사례를 그대로 복제하는 목록이 아니라, 여러 샘플을 제작할 수 있도록 공통 기능과 유형별 전용 기능을 추출한 기준표다.

이 문서는 다음 판단에 사용한다.

1. v2에서 반드시 지원할 기능과 후속 기능 구분
2. 탁상형과 벽보형의 공통 기반 및 전용 Runtime 분리
3. Studio, Workspace, 미리보기, 출력에서 동일하게 보장할 동작 정의
4. 현재 코드의 유지·보강·교체·신규 판정
5. 대표 샘플 기반 구현 및 회귀 테스트 범위 선정

## 2. v2 제품 범위

> 실제 학사달력 샘플을 기반으로 탁상형과 벽보형 달력을 안정적으로 제작·편집·사용·출력할 수 있는 공통 에디터 구조를 확립한다.

### 2.1 제품 유형의 본질

| 구분 | 탁상형 | 벽보형 |
|---|---|---|
| 제품 성격 | 반복 페이지 생성 시스템 | 영역 기반 출판 레이아웃 시스템 |
| 기본 단위 | 월별 앞·뒤 페이지 페어 | 대형 지면의 월 블록·일정·정보 영역 |
| 대표 구성 | 표지, 연력, 학교 상징, 월별 뒷면, 월력, 뒷표지 | 연간·학기 월력, 일정 목록, 셀 일정, 학교 운영정보 |
| 핵심 자동화 | 페이지 순서와 월별 반복 생성 | 일정 흐름, 충돌, 공간 초과 관리 |
| 주요 사용자 입력 | 학교정보, 일정, 월별 사진·문구 | 일정, 학교정보, 학기 범위, 부가정보 표 |
| 핵심 출력 위험 | 앞뒤 순서, 페이지 누락, 이미지 해상도 | 과밀, 일정 누락, 글자 축소, 충돌·잘림 |

두 유형은 공통 데이터와 개체 Runtime을 공유하지만 페이지 구성 Runtime은 분리한다.

## 3. 우선순위 기준

| 등급 | 의미 |
|---|---|
| P0 | v2 기반을 성립시키는 필수 기능. 없으면 대표 샘플 제작 또는 출력 검증이 불가능함 |
| P1 | v2 핵심 지원 기능. 주요 샘플 범위를 확장하고 실사용 완성도를 결정함 |
| P2 | 후속 고도화. 자동화·편의성·표현 범위를 확대함 |

## 5. 탁상형 기능 매트릭스

### 5.1 페이지 구조

실제 6종 샘플은 모두 28페이지였으며 다음 구조가 반복됐다.

```text
표지 앞면
연력
학교 상징
[월별 뒷면 + 월력 앞면] × 12개월
뒷표지
```

| 영역 | 기능 | 편집 단위 | Workspace 노출 | 우선순위 | 비고 |
|---|---|---|---|---:|---|
| 페이지 | 의미 기반 `pageRole` | 페이지 | 읽기 | P0 | 배열 순서만으로 의미를 판단하지 않음 |
| 월 페어 | `pairId`, `monthKey`, `side` | 월별 페어 | 월 단위 탐색 | P0 | 앞뒤 인쇄 관계 보장 |
| 반복 | 12개월 페이지 자동 생성 | 마스터·반복 규칙 | 자동 적용 | P0 | 복제본이 아닌 인스턴스·override 구조 |
| 시작월 | 임의 시작월 기준 페이지 생성 | 템플릿 설정 | 선택 | P0 | 3월 시작 지원 |
| 페이지 순서 | 표지·본문·뒷표지 조립 | 제품 시퀀스 | 확인 | P0 | 누락·중복 검사 포함 |
| 월별 차이 | 월별 콘텐츠·스타일 override | 월 인스턴스 | 허용 항목 변경 | P1 | 공통 마스터 상속 |
| 선택 페이지 | 앞·뒤 간지 0장 이상 | 시퀀스 | 추가·제거 허용 가능 | P1 | 템플릿 capability에 따름 |

### 5.3 월별 뒷면

월별 뒷면은 단일 고정 개체가 아니라 개체를 조합한 반복 페이지 템플릿으로 정의한다.

| 프리셋 계열 | 주요 구성 | 우선순위 |
|---|---|---:|
| 월 목표·주간 플래너 | Monthly Goal, Weekly Planner, To-do, Memo | P0 |
| 이미지 콜라주+띠력 | 다중 이미지 프레임, 월 제목, 일렬 날짜 | P1 |
| 큰 이미지+미니달력 | 대표 이미지, 현재·인접 월 미니달력 | P1 |
| 할 일·메모 | 체크리스트, 목표, 메모 영역 | P1 |

필수 원칙:

- 뒷면 프리셋은 내부적으로 여러 개체로 구성한다.
- Studio에서는 구성과 잠금 범위를 편집할 수 있다.
- Workspace에서는 주로 사진·문구·체크 항목 등 콘텐츠만 교체한다.
- 12개월 전체에 같은 프리셋을 적용하되 월별 override를 허용한다.

### 5.4 이미지·월별 디자인

|---|---:|---:|---:|

| 콜라주 프리셋 | 구성 | 프리셋 선택 또는 고정 | P1 |
| 크롭·초점 | 기본값 설정 | 조정 | P0 |
| 프레임 마스크·라운드 | 설정 | 보통 잠금 | P1 |
| 월별 이미지 바인딩 | 설정 | 업로드·선택 | P0 |
| 월별 테마 색상 | 테마 세트 구성 | 허용 시 선택 | P1 |
| 계절 장식 자산 | 배치 | 보통 잠금 | P1 |
| 저해상도 경고 | 확인 | 확인·교체 | P0 |

### 5.5 탁상형 Workspace 권장 권한

기본 허용:

- 학교정보와 학교 상징 입력
- 학사일정 입력·수정
- 월별 사진 교체와 초점 조정
- 월별 대표 문구 수정
- 템플릿이 허용한 테마 또는 뒷면 프리셋 선택

기본 잠금:

- 페이지 마스터 구조
- 인쇄 규격과 안전영역
- 개체 위치와 크기
- 반복 규칙과 페이지 페어
- 디자이너 장식 자산

## 6. 벽보형 기능 매트릭스

### 6.1 구성 계열

| 계열 | 핵심 구조 | 필요한 상위 블록 | 우선순위 |
|---|---|---|---:|
| 월력+별도 일정 목록 | 작은 월력과 월별 일정 목록 | Month Block | P0 |
| 월력 셀 내부 일정 | 큰 셀 안 일정과 기간 막대 | Calendar Grid + Event Layer | P1 |
| 월력+학교 운영정보 | 달력과 현황·시간표·교육목표 | Information Block·Table | P1 |
| 학기·범위 분할 | 한 장 또는 두 장에 월 범위 분배 | Page Composition | P1 |

### 6.2 페이지와 월 범위

| 기능 | 설명 | 우선순위 |
|---|---|---:|
| 단일 페이지 전 학년 | 12개월을 한 지면에 구성 | P0 |
| 학기 분할 | 1학기·2학기를 페이지별 구성 | P1 |
| 임의 월 범위 | 페이지마다 `monthRange` 선언 | P1 |
| 달력+정보 페이지 | 한 페이지는 달력, 다른 페이지는 학교정보 | P1 |
| 지면 방향·규격 | 세로·가로 대형 인쇄물 | P0 |

### 6.3 일정 표현

| 표현 방식 | Runtime 책임 | 우선순위 |
|---|---|---:|
| 월별 일정 목록 | 날짜·기간 포맷, 정렬, 줄바꿈 | P0 |
| 셀 내부 단일 일정 | 날짜 영역과 일정 영역 분리 | P1 |
| 한 주 기간 막대 | 주 안에서 시작·끝 열 계산 | P1 |
| 여러 주 기간 일정 | 주 경계별 segment 분할 | P1 |
| 동일 날짜 다중 일정 | 우선순위와 lane 배치 | P1 |
| 별도 전체 일정표 | 월별 그룹·다단 흐름 | P1 |
| 표 형식 일정 | 행·열·셀 스타일과 데이터 바인딩 | P1 |
| 짧은 표시명 | 공간에 따른 표시명 override | P1 |

하나의 일정 데이터가 여러 표현 영역에 동시에 바인딩될 수 있어야 한다. 예를 들어 같은 기간 일정이 월력에는 막대로, 일정 목록에는 날짜 범위를 포함한 텍스트로 표시될 수 있다.

### 6.4 자동 레이아웃 수준

| 수준 | 동작 | v2 적용 |
|---|---|---|
| L1 고정 레이아웃 | 영역 위치·크기 고정, 초과 시 경고 | P0 |
| L2 영역 내부 조정 | 글자 축소, 행간 조정, 다단 흐름 | P1 |
| L3 지면 재배치 | 일정량에 따라 영역 크기·페이지 재구성 | P2 |

v2의 현실적인 완료선은 L2다. L3는 Publishing Geometry Runtime 고도화 단계에서 구현한다.

### 6.5 부가 운영정보

| 블록 | 데이터 예 | 우선순위 |
|---|---|---:|
| 학교 현황 | 학급 수, 학생 수, 교직원 수 | P1 |
| 일과 운영 | 교시, 시작·종료 시간 | P1 |
| 방과후 프로그램 | 요일, 시간, 프로그램, 장소 | P1 |
| 교육 목표 | 목표·중점 과제·슬로건 | P2 |
| 연락처·안내 | 주소, 전화, 홈페이지 | P1 |

부가정보는 범용 텍스트로만 처리하지 않고 구조화된 Table 또는 Information Block으로 지원한다.

### 6.6 벽보형 Workspace 상태 표시

| 상태 | 의미 | 사용자 조치 |
|---|---|---|
| 정상 | 모든 콘텐츠가 허용 영역에 배치됨 | 없음 |
| 공간 부족 주의 | 임계치에 근접함 | 일정 축약 또는 영역 검토 |
| 자동 축소 적용 | 허용 범위 안에서 글자 크기가 축소됨 | 결과 확인 |
| 최소 크기 미달 | 가독성 기준 이하가 필요함 | 일정 축약·분할·디자이너 조정 |
| 일부 일정 미표시 | 표시 한도를 초과함 | 숨김 일정 확인 및 수정 |
| 디자이너 조정 필요 | 자동 처리로 안전한 출력 불가 | Studio에서 레이아웃 조정 |

## 7. 삽입 메뉴에 노출할 완성형 블록

내부 개체를 모두 개별 메뉴로 노출하지 않는다. 사용자가 목적 단위로 이해할 수 있는 블록을 제공한다.

## 10. 수용 기준

v2 기능은 화면에서 보인다는 이유만으로 완료 처리하지 않는다. 각 기능은 다음을 모두 통과해야 한다.

1. Schema 저장·불러오기 후 결과가 동일하다.
2. Studio와 Workspace에서 같은 데이터가 같은 방식으로 렌더링된다.
3. 미리보기와 최종 출력의 위치·줄바꿈·크롭 결과가 일치한다.
4. 지원 범위를 넘는 콘텐츠는 경고 또는 오류로 드러난다.
5. 다른 상품 유형과 기존 템플릿의 회귀 테스트를 통과한다.
6. 사용자 권한 밖의 구조 변경은 차단된다.

## 11. 확정 원칙

1. 지원 상품은 우선 탁상형과 벽보형으로 제한한다.
2. 템플릿 개수가 아니라 조합 가능한 블록과 Runtime 기능으로 지원 범위를 정의한다.
3. 일정 데이터와 일정 표현을 분리한다.
4. 탁상형은 월별 앞뒤 페이지 페어를 기본 단위로 한다.
5. 벽보형은 자유 캔버스에 더해 영역 기반 출판 레이아웃을 사용한다.
6. 월별 뒷면은 조합 가능한 반복 페이지다.
7. 월별 변화는 페이지 복제가 아니라 override로 관리한다.
8. Studio와 Workspace는 동일 Schema와 Runtime을 사용한다.
9. 모든 자동 레이아웃에는 오버플로 감지와 출력 검사가 따른다.
10. 학교 현황과 시간표를 벽보형의 정식 구성 요소로 인정한다.
